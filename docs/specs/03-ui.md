# UI spec

> Last verified: 2026-10-20 · Scope: ui/ (app.py, views.py, style.py, bridge.py, .streamlit/config.toml, static/) and
> docs/design/. The pipeline, clients and replay pacing are in [01-architecture.md](01-architecture.md); the copy and
> numbers the talk depends on are in [05-demo-content.md](05-demo-content.md).

## 1. Purpose & scope

The UI is the Streamlit chatbot the presenter drives live: pick or upload the requirements, watch each agent work (live
card), read its result card, then approve or ask for changes at a sticky gate. It must match the approved mockups at
4K and on a projector, survive clicks, reloads and slow agents mid-talk, and switch to Replay without looking different.

| File | Responsibility |
|---|---|
| [ui/app.py](../../ui/app.py) | Shell: page config, session state, query params, nav, top bar, welcome, transcript loop, gate, dialogs, chat bar, scroll triggers, all button callbacks |
| [ui/views.py](../../ui/views.py) | Stage messages: live card (phases, timeline, narration), result card (facts → headline, KPIs, evidence, tabs, bridge), FinOps chart, finale, files browser. Pure helpers plus render functions |
| [ui/style.py](../../ui/style.py) | Design system: `STAGE_META`, `TOKENS`/`DARK_TOKENS`, `CSS`/`DARK_CSS`/`PRESENTER_CSS`, `title_case`/`sentence_case`, HTML fragments (nav, crumb, strip, cards, dialogs), JS snippets (scroll, nav, focus) |
| [ui/bridge.py](../../ui/bridge.py) | `StageJob` (one stage attempt on a daemon thread) and `RunRegistry` (process-wide, `st.cache_resource`) |
| [ui/.streamlit/config.toml](../../ui/.streamlit/config.toml) | Script-level config (overrides project and global config): light theme base, Inter font faces, static serving |
| [ui/static/](../../ui/static/) | Self-hosted Inter 300/400/500/600, the Material Symbols Rounded subset, their licences |
| [docs/design/](../design/) | The approved look: three mockups and [GUIDELINES.md](../design/GUIDELINES.md) (capitalization, numbers) |

## 2. Invariants

1. **The approved look** is [mockup-welcome.html](../design/mockup-welcome.html),
   [mockup-stage.html](../design/mockup-stage.html) and [mockup-stage-dark.html](../design/mockup-stage-dark.html). A
   visual change MUST match them; a new look MUST land in the mockups first (recipe f). Compare rendered pixels, not CSS
   numbers: style.py deviates on purpose where Streamlit's DOM needs it (e.g. `.st-key-welcome` top padding
   `calc(9vh + 27px)` vs `9vh`), and `ink3` is `#737380`, not the mockup's `#8b8b97`, to keep AA on white.
2. **Capitalization** ([GUIDELINES.md](../design/GUIDELINES.md)): Title Case for anything that *names* (buttons, tabs,
   menu items, toggles, dialog and section titles, column headers, KPI labels, status words, chips); sentence case for
   anything that *says* (headlines, captions, gate messages, placeholders, toasts, model text). Dynamic labels MUST go
   through `title_case()` (table headers, kv labels, KPI labels, phase and timeline rows already do), KPI captions
   through `sentence_case()`. Product names and acronyms keep their casing (`PROTECTED` in style.py, `ACRONYMS` in
   views.py).
3. **Numbers.** Hero numbers (KPIs, finale tiles, chart totals) MUST be Inter Light 300, −0.02em,
   `tabular-nums lining-nums` (`.tx-kpi-v`, `figure_html`); units and denominators small, grey, weight 400 (`<small>`),
   a leading "$" at .7em (`.tx-cur`), arrows quieter (`.tx-arr`). Format only through views helpers: `money()` ($1,250,
   never "$365.0"), `fmt_secs()` (9.8 s), `fmt_tokens()` (14.4k), `fmt_pct()`. Colour a number only for meaning
   (`Kpi.color` red | green | orange → `tx-bad` | `tx-good` | `tx-warn`).
4. **Type.** Inter weights 300/400/500/600 only. 700/bold MUST NOT appear in CSS, `headingFontWeights` or ui/static
   (`test_no_bold_700_anywhere`). Smallest text 11.5 px (`test_small_text_stays_legible_and_no_robot_or_sparkle_icons`).
5. **No emojis, no orange, no Microsoft branding.** Icons are Material Symbols Rounded line icons (wght 300, opsz 20,
   FILL 0) from the self-hosted subset; no robot or sparkle glyphs (`smart_toy`, `auto_awesome`). Streamlit's "orange"
   and "yellow" slots and the `orange` KPI tone map to the amber warn token `#a15c07`. No Fluent/Segoe/Teams names or
   look-alike assets.
6. **Contrast.** Text MUST meet WCAG AA (4.5:1; 3:1 only for large text, ≥24 px) on card and pane in both themes.
   Today: light ink3 on white 4.67:1, dark ink3 on `#191823` 5.52:1. Known gap: debt 11.
7. **Sanitizer.** The text of any `<style>` block (`CSS`, `DARK_CSS`, `PRESENTER_CSS`, `views.CSS`) MUST NOT contain "<"
   followed by a letter, "/" or "!", comments included: `st.html` runs DOMPurify, which drops the whole style element
   (`test_css_survives_the_html_sanitizer` greps `<[a-zA-Z/!]`).
8. **Tokens.** Every colour MUST come from `TOKENS`/`DARK_TOKENS` through `--tx-*` custom properties (`_ROOT`, `_DARK`);
   rules and inline HTML use `var(--tx-*)` (as `PHASE_LOOK` does), never a hex. Vega can't read CSS, so charts use
   `CHART_PALETTES` per theme. Light mode MUST stay pixel-identical when dark styles change and vice versa: dark-only
   fixes go in `_DARK`, never `_CSS`; any `_CSS` change MUST be checked in both themes. Existing literals: debt 10.
9. **Gate.** After every finished result the gate MUST be visible (sticky bar `.st-key-gate`, or the `.st-key-gate-step`
   card) and MUST NOT render while an agent works. One change path: the Ask for Changes dialog (`send_feedback_form`)
   and the chat bar (`on_chat`) MUST both end in `request_changes(stage, text)` → `start_stage(stage, feedback)`.
10. **Render functions never raise.** Facts are pure and tolerant (`as_dict`, `rows_of`, `num`, `whole`); sections run
    in `guarded()`; an off-contract result shows `st.info` plus raw data; `render_final`, `render_finale`,
    `keyed_container`, `tool_outcome` and table cells each catch. Text into `st.markdown` MUST pass `esc()` (HTML, "$" →
    `&#36;`) or `md()` (markdown, `\$`): a bare "$" starts KaTeX math.
11. **Never block or cancel a running stage.** Agents MUST run in a `StageJob` registered in `RunRegistry`; the script
    only polls (`follow()`). Any click, reload or second browser re-attaches (`REG.job`, `attach_from_url`, `open_run`);
    nothing may reload a run from disk while its job is live. Controls that would orphan a job (mode switch, Replay
    toggle, Start a New Run, Resume, uploads, chat) MUST be disabled while `busy()`.
12. **Icon-only buttons are exactly centred** (theme toggle, "…", New Run): a 34×34 button; the icon
    (`[data-testid="stIconMaterial"]`) in a 20×20 box (`line-height: 20px`, inline-flex centred); every inner div/span
    with gap and margin 0; the button's first div a full-size flex centring box; every hidden label out of flow
    (`position: absolute`, 1×1 px, `clip`). History: the icon box was 15 px for a 20 px glyph and a hidden 1 px label
    pushed the glyph sideways. Labels stay in the DOM (screen readers, `help` tooltip).
13. **Segmented control** (Local · AgentCore): icon and label centred as one unit with equal 16 px side padding; the
    selected segment has no focus ring (`button:focus` and `:focus-visible` outline none; only unselected segments get an
    inset ring on keyboard focus).
14. **Honest Plan B.** In Replay the crumb MUST show the "Recorded Run" chip (Fake: "Demo Data"). The Replay suggestion
    card shows only when Replay is on or no AWS credentials exist (`replay_card_wanted`).
15. **"…" menu labels** are quoted verbatim by [WORKSHOP.md](../../WORKSHOP.md) and
    [KEYNOTE-SCRIPT.md](../KEYNOTE-SCRIPT.md): heads This Run · Live Options · Plan B; Resume a Run; Live AWS Discovery
    (EC2 + CloudWatch) · Live Deploy to kind · Simulate Manual Drift (Demo) · Live AWS Pricing · Show AWS Transform
    Notes; Replay a Recorded Run (Offline), or "Replay (Available When No Agent Is Running)" while busy; Replay From.
    Every menu toggle MUST use the `<key>_w` mirror (`MENU_TOGGLES`, `sync_menu_toggles`), or opening the menu resets it.
16. **URL state.** `?run=<id>`, `?presenter=1` and `?theme=dark` MUST survive a reload; New Run removes only `run`.

## 3. Architecture of the UI

**Page flow** (bottom of app.py, every rerun): inject styles → `sync_theme_param` → `attach_from_url` → `sidebar()`
(nav) → `topbar()` (crumb, switch, theme, "…", New Run, presenter strip) → `hero_slot` → `transcript` container →
`gate_slot` (reserved *before* the transcript blocks, so no stale gate lingers) → `scroll_slot` → `chat_bar()` → toast →
`welcome()` (no pipeline) → `render_transcript()` (blocks in `follow()` on a live job, then `st.rerun()`) → `gate()` →
repaint nav and strip → `landing_scroll()`.

**Session state** (`ss = st.session_state`):

| Key | Meaning |
|---|---|
| `transcript` | `{"kind": "user" \| "note", "text"}` or `{"kind": "stage", "job": StageJob}` entries |
| `pipeline`, `job` | The run's `Pipeline` (same object as the registry's) or None (welcome); its latest `StageJob` |
| `requirements` | `(filename, text)`; `upload-id-<key>` remembers the last processed upload |
| `mode`, `live_mode` | Single source of truth: `local` \| `agentcore` \| `replay` \| `fake`; where turning Replay/Fake off returns |
| `live_aws`, `live_deploy`, `live_pricing`, `simulate_drift` | `Options` fields (`OPTION_KEYS`); copied from the run by `open_run` |
| `show_bridges` | Bridge strip on (default) or off; read by views.py |
| `theme`, `presenter` | `light` \| `dark`; mirror of `?presenter=1` (read by views.py) |
| `show_feedback`, `feedback_hint` | Ask for Changes dialog open; empty-submit hint |
| `scrolled` | Scroll phases already played (each plays once) |
| `client`, `client_key`, `attached`, `toast` | Client cached per (mode, replay source); run re-attached from the URL; one-shot toast |
| Widget keys | `mode_seg`, `replay_on`, `fake_on`, `<key>_w` (`MENU_TOGGLES`), `chat`, `feedback_text`, `resume_id`, `replay_from`; popovers `new_run_menu`, `more_menu` (set to False to close) |

**Query params.** `run` is set by `start_migration` and `open_run`, removed by `new_run`; a new session re-attaches once
(`attach_from_url`, guarded by `ss.attached`). `presenter=1` is read at the top of every run (`PRESENTER`; collapses
the nav, adds `PRESENTER_CSS`). `theme=dark` seeds `ss.theme`; `sync_theme_param` writes it back every run.

**Modes.** `ss.mode` defaults to `UI_MODE` (default `local`); `fake` exists only with `UI_ENABLE_FAKE=1`. The top-bar
segmented control shows `LIVE_MODES` (Local, AgentCore; labels in `MODE_LABELS`) and is disabled while busy; Replay is a
Plan B toggle in the "…" menu (or the welcome card, `switch_to_replay`), Fake a menu toggle. `sync_mode_widgets` pushes
`ss.mode` into the widgets every run (`mode_seg` is None while Replay/Fake is on).

**Threading** ([bridge.py](../../ui/bridge.py)). `start_stage` → `REG.start(run_id, make_job)` creates one `StageJob`
per run (None if one is live). The job's daemon thread drives the pipeline's async generator on its own event loop and
appends events to `job.events` (atomic list append); `done` flips as soon as the stream ends, not after executor
cleanup (2 s cap). `RunRegistry` holds pipelines and latest jobs per run id, shared by every session.
`render_transcript` builds a `StageView` per entry: finished → `render_final()`; live → `follow()` polls every 0.15 s,
repaints on new events or every 1 s, returns when done, then `st.rerun()` draws the card and the gate. A click mid-stage
stops only the script run; the next run re-attaches to the same job. `rebuild_transcript` rebuilds a run's chat from
`Pipeline.attempts()`.

**Auto-scroll.** `scroll_once(target, phase, land)` emits `scroll_html` (an `st.html` script with
`unsafe_allow_javascript`) once per phase: `<job id>:start` (live card), `<job id>:landed` with `land=True` (finished
result), `<run id>:finale`, `top` (welcome). `_SCROLL_JS` finds the real scroller and keeps `--tx-top-offset` clear
(84 px; 150 px in presenter mode; px_to_rem leaves it in px for the script). Landing keeps header, headline, KPIs and
evidence above the sticky gate, capped at the headline; settle passes at 700 and 1600 ms stop once the presenter
scrolls, clicks or types. It depends on `.tx-kpis`, `.tx2-headline`, `.st-key-gate`, `[data-testid="stTabs"]`,
`[data-testid="stBottom"]` and `[data-testid="stMainBlockContainer"]`: rename one and landing breaks silently. Script
holders (`.tx-scroll`) are hidden by CSS. `NAV_JS` (one delegated click handler) scrolls a nav row's
`data-tx-target` card into view; `FOCUS_JS` focuses the dialog textarea for ~1.2 s.

**Container-key contract.** Streamlit adds `st-key-<key>` to keyed containers and widgets; style.py targets them.
app.py: `topbar` (`tb-row`, `tb-left`, `tb-mid`, `tb-right`), `welcome`, `welcome-input`, `suggestions`, `sg-sample`,
`sg-replay`, `sg-legacy`, `sg-agents`, `transcript`, `stage-<job id>` (scroll and nav anchor), `gate`, `gate-row`,
`gate-step`, `wrapup`, `recap`; widget keys `theme_toggle`, `more_menu`, `new_run_menu`. views.py (`container_key`,
`keyed_container`): `live-<stage>`, `card-<stage>` (attempt ≥ 2 adds `-<attempt>`), `process-<stage>-<attempt>-<job id>`,
`finale`. Selectors such as `[class*="st-key-card-"]` match by substring, so new keys MUST NOT start with `card-`,
`live-`, `stage-`, `process-` or `sg-`. The docstring lists in views.py and style.py are stale (debt 6).

**CSS architecture.** `CSS = <style> + px_to_rem(_ROOT.substitute(**TOKENS, mesh=MESH) + _CSS) + </style>`. `_ROOT` maps
tokens to `--tx-*` and adds surface, shadow and state variables (`--tx-card`, `--tx-float`, `--tx-seg-on`, …).
`px_to_rem` turns every size above 2 px into rem at the 15 px root (`BASE_PX`), except `@media` lines, lines marked
`/* px */` and `--tx-top-offset`; `html { font-size: calc(15px * var(--tx-scale)) }` makes presenter mode one variable.
app.py injects `CSS + css_block(views.CSS) + PRESENTER_CSS (presenter) + DARK_CSS (dark)` in one `st.html` call.
`PRESENTER_CSS` only sets `--tx-scale: 1.2` and `--tx-top-offset: 150px`. `DARK_CSS` (`_DARK`, a `Template` over the
whole block: write "$" as "$$") redefines the variables from `DARK_TOKENS` plus `DARK_MESH`, sets `color-scheme: dark`,
and repaints what Streamlit draws with its light theme, including portals (BaseWeb popovers and menus, react-aria
select dropdowns, tooltips, dialogs, toasts, code, JSON, checkboxes, alerts, disabled inputs). Light mode is the base CSS
alone. config.toml keeps `base = "light"` and mirrors the light palette for Streamlit's own widgets. Selectors use
`data-testid`/ARIA attributes of Streamlit 1.66.0 (uv.lock), never `st-emotion-cache-*`; re-check them on any upgrade.

**Charts.** `cost_chart()` (Altair, FinOps only) takes colours from `CHART_PALETTES["light"]` (built from `T`, i.e.
`TOKENS` chart_* and ink*) or `["dark"]` (literals) via `dark=dark_theme()`, and `scale=1.2` in presenter mode;
`CHART_HEIGHT = 230` so alert plus chart land above the gate at 1280×720. config.toml `chartCategoricalColors` and
`chartSequentialColors` only affect native Streamlit charts (none today).

**Fonts.** Inter 4.x static woff2 (name table "Version 4.001"; full glyph set with `cv11`, `ss01`, `ss03`, `tnum`) in
ui/static, declared in config.toml `[[theme.fontFaces]]` (`url = "app/static/Inter-<Weight>.woff2"`, weights 300, 400,
500, 600); `enableStaticServing = true` serves ui/static (the folder next to the main script) at `app/static/`. The CSS
enables `font-feature-settings: "cv11", "ss01", "ss03"` like the mockups.

**Icons.** `@font-face "TX Symbols"` loads `app/static/MaterialSymbolsRounded.woff2` (wght axis 100–700 only; opsz 20,
FILL 0, GRAD 0 baked in) and applies it to `.tx-ms` (`ms()` in style.py, `ic()`/`tile()` in views.py),
`[data-testid="stIconMaterial"]` and `[data-testid="stExpanderIcon"]`, so Streamlit's own icons (widget `icon=`, chat
avatars, expander chevrons, sidebar arrows) use the subset too, with Streamlit's font as fallback. The subset holds 199
ligatures, aliases and Streamlit's internal names included. Names the code uses (45): add, arrow_forward, build, chat,
chat_bubble, check, check_circle, checklist, cloud, code, conversion_path, dark_mode, data_object, database,
deployed_code, description, dns, do_not_disturb_on, download, edit, edit_note, error, explore, groups, history,
hourglass_top, hub, info, laptop_mac, light_mode, lightbulb, more_horiz, person, play_arrow, progress_activity,
radio_button_unchecked, refresh, rule, savings, sell, send, stacks, travel_explore, verified, warning. The welcome "+"
is the ligature `add` in a CSS `content:`. No regeneration script exists yet (recipe g, debt 7).

## 5. Change recipes

**(a) Add or modify a KPI or card section for a stage**
1. Confirm the field in [docs/CONTRACTS.md](../CONTRACTS.md), `samples/recorded-run/<stage>/result.json` and
   `tests/fixtures/<stage>_result.json`.
2. Extract it in `<stage>_facts()` (pure, tolerant helpers, None when absent).
3. KPI: edit the stage branch of `stage_kpis()`. Label: Title Case noun. Value in a `figure_html` form ("17", "62/100",
   "$450/mo", "9.8 s", "4 → 0"; anything else renders as text). Caption: lowercase sentence. Colour only for meaning.
   Replace rather than add: the list is cut to `k[:3]` and the tests require exactly three per recorded stage.
4. Keep `headline()` (one deterministic sentence, never the model's summary) and `evidence()` (one line at presenter
   scale) consistent with the KPIs.
5. Section: add to `<stage>_overview`/`<stage>_details` with `subhead`, `kv`, `table` (cell kinds id, code, sev, result,
   num, muted), `note_block`, `html_block`. Never `st.metric` or `st.dataframe`.
6. Finale: `finale_tiles` (and `finale_rows` widths) if the number belongs in the wrap-up.
7. Check landing in presenter mode at 1280×720 and 1920×1080: header, headline and KPIs clear the gate.
8. Tests: extend [test_views.py](../../tests/test_views.py) (labels and values from recorded data; `ODD_VALUES` must not
   raise).

**(b) Add a design token and use it in both themes**
1. Add the key to `TOKENS` and `DARK_TOKENS` (`Template.substitute` raises `KeyError` at import if one lacks it).
2. Declare `--tx-<name>: $<name>;` in `_ROOT` and in `_DARK`. Surface variables without a token key (light `--tx-card:
   #fff`) are literal in `_ROOT` and overridden in `_DARK`.
3. Use `var(--tx-<name>)` in `_CSS` or inline views HTML; charts: add it to both `CHART_PALETTES`.
4. Contrast-check every text pair in both themes; extend the night-palette list in
   `test_dark_css_only_swaps_tokens_and_light_css_has_no_hard_coded_surfaces` with the new dark value.
5. Capture light before and after: identical except the intended change.

**(c) Add a widget and style it in light and dark**
1. Give it a key (or wrap it in `st.container(key=...)`) and scope rules under `.st-key-<key>`.
2. Select by `data-testid` and ARIA (`[aria-checked]`, `[kind]`, `[role]`), checked against the DOM of the pinned
   Streamlit. Write px; px_to_rem converts it (mark `/* px */` to keep px).
3. Light rules in `_CSS` with `var(--tx-*)`; dark overrides in `_DARK` for backgrounds, text, borders, placeholders and
   `-webkit-text-fill-color` (Streamlit paints widgets with its light theme).
4. Portals render at body level, outside `.st-key-*`: style popover bodies, select dropdowns, menus, tooltips, dialogs
   and toasts through `[data-baseweb="popover" | "menu" | "tooltip"]`, `[data-testid="stPopoverBody" |
   "stSelectboxVirtualDropdown" | "stTooltipContent" | "stDialog" | "stToast"]`, in both blocks; add new portal
   selectors to the dark CSS test list.
5. Icons: `icon=":material/<name>:"` with a name in the subset (else recipe g). Icon-only buttons: invariant 12 pattern

Each item verified against the working tree on 2026-10-20.

1. **`friendly_model`/`MODEL_NAMES` duplicated and diverged**: style.py (nav footer) vs views.py (telemetry, live

   views.py repeats them in `_TOKEN_DEFAULTS`, a full copy of `TOKENS`; `views.DESIGNED_OVER` is unused.

   streamlit 1.66.0 depends on both). The `ui` extra says `streamlit>=1.50` while the CSS targets the 1.66 DOM
   (react-aria selects, `stSelectboxVirtualDropdown`, `.react-aria-SelectionIndicator`): raise the floor.

   and omits `process-…`; the style.py comment lists `bridge-<stage> (unused now)`; `test_container_keys_follow_the_shell_contract`
   still asserts `container_key("kpis", …)`.

   note). Commit one with recipe g.

   Inter-Medium.woff2, MaterialSymbolsRounded.woff2, MaterialSymbols-LICENSE.txt and docs/design/ are untracked.
   Committing the modified config.toml and tests without them leaves fonts missing and `test_no_bold_700_anywhere`
   failing. `git rm` the Bold file and add the rest in the same commit.

   icon span by 14 px a side (28 px before the icon, 14 px after the label). The app's ~214 px (16 px padding, 7 px gap)
